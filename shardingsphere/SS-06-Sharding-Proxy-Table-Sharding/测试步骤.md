# Sharding-Proxy 分表功能测试步骤

## 配置说明

根据当前配置 `config-sharding.yaml`：
- **分库策略**：按 `user_id % 2` 分库
  - `user_id % 2 = 0` → `ds_0` (edu_1)
  - `user_id % 2 = 1` → `ds_1` (edu_2)
- **分表策略**：按 `order_id % 2` 分表
  - `order_id % 2 = 0` → `t_order_0` / `t_order_item_0`
  - `order_id % 2 = 1` → `t_order_1` / `t_order_item_1`
- **实际数据节点**：
  - `ds_0.t_order_0`, `ds_0.t_order_1`
  - `ds_0.t_order_item_0`, `ds_0.t_order_item_1`
  - `ds_1.t_order_0`, `ds_1.t_order_1`
  - `ds_1.t_order_item_0`, `ds_1.t_order_item_1`
- **绑定表**：`t_order` 和 `t_order_item`（JOIN 查询时优化）
- **主键生成器**：SNOWFLAKE（自动生成 order_id 和 order_item_id）

---

## 测试步骤

### 步骤 1：连接 Sharding-Proxy

Sharding-Proxy 默认端口是 **3307**（如果配置了其他端口，请相应调整）。

```bash
# 使用 MySQL 客户端连接
mysql -h127.0.0.1 -P3307 -usharding -psharding

# 或者使用 root 用户（但需要先 use sharding_db）
mysql -h127.0.0.1 -P3307 -uroot -proot
```

连接成功后，切换到逻辑库：
```sql
USE sharding_db;
```

---

### 步骤 2：创建表结构

在 Sharding-Proxy 中创建逻辑表（不需要指定分表后缀）：

```sql
-- 创建订单表
CREATE TABLE IF NOT EXISTS t_order (
    order_id BIGINT NOT NULL,
    user_id INT NOT NULL,
    status VARCHAR(50),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 创建订单项表
CREATE TABLE IF NOT EXISTS t_order_item (
    order_item_id BIGINT NOT NULL,
    order_id BIGINT NOT NULL,
    user_id INT NOT NULL,
    product_name VARCHAR(100),
    quantity INT,
    price DECIMAL(10,2),
    PRIMARY KEY (order_item_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**注意**：Sharding-Proxy 会自动根据分表规则在底层数据库中创建对应的物理表。

---

### 步骤 3：验证物理表是否创建成功

直接连接到底层 MySQL 数据库验证：

```bash
# 连接 ds_0 对应的数据库
mysql -h192.168.56.11 -P3306 -uremote_user -pRemotePassword123! edu_1

# 查看表
SHOW TABLES;
# 应该能看到：t_order_0, t_order_1, t_order_item_0, t_order_item_1

# 连接 ds_1 对应的数据库
mysql -h192.168.56.11 -P3306 -uremote_user -pRemotePassword123! edu_2

# 查看表
SHOW TABLES;
# 应该能看到：t_order_0, t_order_1, t_order_item_0, t_order_item_1
```

### 步骤 4：插入测试数据（验证分库分表）

回到 Sharding-Proxy 连接，插入测试数据：

```sql
USE sharding_db;

-- 测试数据 1：user_id=100 (100%2=0 → ds_0), order_id 由 SNOWFLAKE 生成
-- 注意：由于 order_id 是 SNOWFLAKE 生成，我们需要先插入，然后查看实际生成的 order_id
INSERT INTO t_order (user_id, status) VALUES (100, 'PENDING');
-- 查看生成的 order_id
SELECT order_id, user_id, status FROM t_order WHERE user_id = 100;

-- 假设生成的 order_id = 1234567890123456789（偶数）
-- 那么会路由到：ds_0.t_order_0

-- 继续插入更多测试数据
INSERT INTO t_order (user_id, status) VALUES (100, 'PAID');
INSERT INTO t_order (user_id, status) VALUES (100, 'SHIPPED');
INSERT INTO t_order (user_id, status) VALUES (101, 'PENDING');  -- user_id=101 (101%2=1 → ds_1)
INSERT INTO t_order (user_id, status) VALUES (101, 'PAID');
INSERT INTO t_order (user_id, status) VALUES (102, 'PENDING');  -- user_id=102 (102%2=0 → ds_0)
INSERT INTO t_order (user_id, status) VALUES (103, 'PENDING');  -- user_id=103 (103%2=1 → ds_1)

-- 插入订单项数据
-- 注意：order_item 的分表规则也是按 order_id % 2，所以需要先知道 order_id
-- 假设我们已知某个 order_id，插入对应的订单项
INSERT INTO t_order_item (order_id, user_id, product_name, quantity, price)
SELECT order_id, user_id, 'Product A', 2, 99.99 FROM t_order WHERE user_id = 100 LIMIT 1;

INSERT INTO t_order_item (order_id, user_id, product_name, quantity, price)
SELECT order_id, user_id, 'Product B', 1, 199.99 FROM t_order WHERE user_id = 101 LIMIT 1;
```

### 步骤 5：验证分库分表效果

#### 5.1 在 Sharding-Proxy 中查询（逻辑表查询）

```sql
USE sharding_db;

-- 查询所有订单（会路由到多个库和表）
SELECT * FROM t_order ORDER BY order_id;

-- 按 user_id 查询（会路由到对应的库）
SELECT * FROM t_order WHERE user_id = 100;  -- 路由到 ds_0
SELECT * FROM t_order WHERE user_id = 101;  -- 路由到 ds_1

-- 按 order_id 查询（会路由到对应的库和表）
-- 假设 order_id = 1234567890123456789（偶数）
SELECT * FROM t_order WHERE order_id = 1234567890123456789;  -- 路由到 ds_X.t_order_0

-- 查询订单和订单项（绑定表 JOIN，会优化为单表查询）
SELECT o.order_id, o.user_id, o.status, oi.product_name, oi.quantity, oi.price
FROM t_order o
JOIN t_order_item oi ON o.order_id = oi.order_id
WHERE o.user_id = 100;
```

#### 5.2 直接查询底层物理表（验证数据分布）

```bash
# 连接 ds_0 (edu_1)
mysql -h192.168.56.11 -P3306 -uremote_user -pRemotePassword123! edu_1

# 查看 ds_0.t_order_0 的数据
SELECT * FROM t_order_0;

# 查看 ds_0.t_order_1 的数据
SELECT * FROM t_order_1;

# 查看 ds_0.t_order_item_0 的数据
SELECT * FROM t_order_item_0;

# 查看 ds_0.t_order_item_1 的数据
SELECT * FROM t_order_item_1;
```

```bash
# 连接 ds_1 (edu_2)
mysql -h192.168.56.11 -P3306 -uremote_user -pRemotePassword123! edu_2

# 查看 ds_1.t_order_0 的数据
SELECT * FROM t_order_0;

# 查看 ds_1.t_order_1 的数据
SELECT * FROM t_order_1;

# 查看 ds_1.t_order_item_0 的数据
SELECT * FROM t_order_item_0;

# 查看 ds_1.t_order_item_1 的数据
SELECT * FROM t_order_item_1;
```

**验证要点**：
- `user_id % 2 = 0` 的数据应该在 `ds_0`（edu_1）中
- `user_id % 2 = 1` 的数据应该在 `ds_1`（edu_2）中
- `order_id % 2 = 0` 的数据应该在 `t_order_0` 或 `t_order_item_0` 中
- `order_id % 2 = 1` 的数据应该在 `t_order_1` 或 `t_order_item_1` 中

## 常见问题

### Q1: 如何查看 SNOWFLAKE 生成的 order_id？
```sql
-- 插入后立即查询
INSERT INTO t_order (user_id, status) VALUES (100, 'PENDING');
SELECT LAST_INSERT_ID();  -- 或者直接查询
SELECT order_id FROM t_order WHERE user_id = 100 ORDER BY order_id DESC LIMIT 1;
```

### Q2: 如何手动指定 order_id 进行测试？
```sql
-- 可以手动插入指定 order_id（用于测试分表规则）
INSERT INTO t_order (order_id, user_id, status) VALUES (100, 100, 'PENDING');  -- 偶数 → t_order_0
INSERT INTO t_order (order_id, user_id, status) VALUES (101, 100, 'PENDING');  -- 奇数 → t_order_1
```

### Q3: 如何验证绑定表优化？
绑定表 JOIN 时，Sharding-Proxy 会优化为单表查询。查看日志中的实际 SQL，应该只查询一个物理表，而不是多个表的 UNION。
